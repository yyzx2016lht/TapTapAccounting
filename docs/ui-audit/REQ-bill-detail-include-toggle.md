# 需求：账单详情底部弹层里「计入统计」的呈现方式

> 这是一份交给外部设计/实现的独立需求说明，不依赖阅读本仓库其他文档。
> 背景图：`screenshots/req_01_sheet_top.png`（当前实况，1080x2400）

---

## 1. 这个功能是什么

记账 App 的每一笔账单有一个布尔属性 `excludeFromStats`：

- `false`（默认）→ 这笔账参与统计，会计入本月总支出/总收入、预算进度、饼图、洞察
- `true` → 这笔账**不参与**任何统计，但仍正常显示在账单列表里

用户看到的效果是：账单列表里明明有这笔支出，但统计页的本月总支出里没有它。

## 2. 这个属性的真实分布（关键前提）

**99% 以上的账单都是 `false`。** 它的值只会来自这几处：

| 来源 | 代码位置 | 值 |
|---|---|---|
| 换币平账（历史数据迁移） | `AppDatabase.kt:309-319` | `true` |
| 投资自动收益 | `InvestmentInterestService.kt:518` | `true` |
| 余额调整时用户手选"不计入" | `BalanceAdjustmentActivity.kt:156` | 用户选 |
| CSV 导入的"不计收支"类型 | `CsvManager.kt:33` | `true` |
| 数据库默认值 | `Bill.kt:69` | `false` |

也就是说：**默认状态是"计入"，且这个默认值通常不需要任何 UI 表达。**

## 4. 问题：标签无法自解释

「计入」这个控件要同时承担两件事，但一个两字标签说不清：

- **表达当前状态**：「计入」= 现在统计里算它
- **表达点击后果**：点一下 → 变成不计入

原始实现标签表示**状态**，于是出现"标签说的和点击要做的事相反"：

> 当前这笔记账 `excludeFromStats = true`（不计入），按钮显示「计入」。
> 用户扫一眼的理解是"哦这笔记账没被统计"，于是想点一下把它计入。
> 但点下去的效果恰恰是让它变成不计入。

本轮把标签改成了**表示点击后果**（现在计入中 → 按钮写「不计入」），歧义消除了一半，但暴露出更根本的问题：

> **无论哪种写法，界面上都无法一眼看出这笔记账到底算不算统计。**
> 标签永远和现状矛盾（它描述的是"点下去会变成什么"，不是"现在是什么"）。

## 5. 硬约束（用户明确提出）

- **弹层高度已经用完了。** 当前 6 行内容正好填满可用区域且**不需要滚动**（见背景图）。再加第 7 行会让弹层超高、需要滚动才能看全。用户明确拒绝任何"新增一行"的方案。
- **不能改动记账表单和编辑页。** `activity_edit_bill.xml` 里没有任何 `excludeFromStats` 相关的控件，不要往那里加。
- **不能依赖全屏详情页。** `BillDetailActivity.kt:214` 有一个正规的 Switch，但入口被 `Prefs.isIndependentDetailEnabled(...)` 门控（`HomeBillSheetsController.kt:277`），默认配置下普通用户到不了那个页面。

## 6. 已经考虑过并被否决的方案

> 这一节是为了避免重复劳动，请勿再提。

| 方案 | 为什么否决 |
|---|---|
| 标签改成"点了会怎样"（`计入` ⇄ `不计入`） | 已实现。消除了"标签与后果相反"，但**丢失了状态可见性**——用户看不出这笔记账现在算不算统计。且默认状态（计入中）下凭空出现一个写着「不计入」的按钮，用户会觉得莫名其妙。 |
| 独立的开关行（`不计入收支统计` + Switch） | 用户否决：**弹层已经放不下了，再加一行太高。** |
| 默认隐藏，仅在 `excludeFromStats == true` 时显示一行灰字 `不计入收支统计 · 点此计入` | 用户否决：同上，加行；且会丢掉"把一笔正常账单改成不计入"的入口。 |
| 默认隐藏，仅在 `excludeFromStats == true` 时在动作行显示「计入统计」 | 用户否决：不加行是可接受的，但这个方案丢掉了"改成不计入"的入口，且按钮出现/消失本身作为状态信号仍然需要用户理解规则。 |
| 保留 toggle，按钮写成带状态的形式（如 `✓ 计入统计` / `○ 不计入统计`） | 未正式验证，但预期问题：动作行 4 个胶囊已经挤满，加符号后宽度不一致。 |

## 7. 一个必须同时满足的需求（容易被忽略）

反过来的场景比正向更严重：**如果一笔账被误设成 `excludeFromStats = true`，用户必须在详情里一眼看到"它不参与统计"，否则会出现"我的支出怎么对不上"且无法自查的问题。**

记账 App 里"数字对不上"是信任问题。一个说不清自己为什么不计入的条目，会让用户开始怀疑整个 App 的数据。
