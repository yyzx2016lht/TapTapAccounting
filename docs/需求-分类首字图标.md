# 需求提示词：分类图标「首字文字图标」的生成规则

## 背景

Android 记账 App（包名 `com.taostudio.tapaccounting`，工程根目录 `E:/FlipAccounting-AI`），
原分类图标整套搬运自「钱迹」App，现已逐步替换为开源图标（Material Symbols 主 + Tabler 辅），
打包在 `app/src/main/assets/icons/`（约 1132 个 PNG），由 `BundledIcons` +
`BundledIconLoader` 挂进 Glide 的 `String → InputStream` 加载链。

## 核心需求（这是重点，之前的实现方向错了）

**分类图标不应该由开发者预先逐张设计。**

用户（App 使用者）在「新增分类 / 修改分类」时输入什么文本，
图标就应该由**这段文本**推导出来，规则是：

> **取用户输入文本的第一个字，渲染成文字图标。**

具体要求：

1. **实时性**：用户在名称输入框打字时，图标预览要**跟着输入同步变化**，
   而不是等保存后才出现。输入「酒店」，预览立刻显示「酒」。
2. **通用性**：不预设分类清单、不预置「酒 / 宠 / 退 / 留」这类固定字符图。
   任何用户输入的文字都要能生成，包括生僻字、用户自造词。
3. **兜底层**：凡是**没有专属图标**的分类（含历史遗留的占位图
   `http://res3.qianjiapp.com/cateic_other.png`，界面上是「···」三个点），
   一律自动改用首字图标。**不允许界面上再出现三个点。**
4. **尊重用户手选**：如果用户明确从图标库里挑了一个真实图标，就用用户挑的，
   不要被首字图标覆盖。
5. **编辑同步**：编辑已有分类时，如果是首字图标，用户改了名字，图标要跟着换成新首字。

## 视觉要求（之前做砸的地方）

**文字图标必须和现有线性图标视觉重量一致，不能显得又小又空。**

实测数据（`app/src/main/assets/icons/` 下 1132 张图标的统计）：

| 指标 | 实测值 |
|---|---|
| 画布尺寸 | 128×128（617 张）、256×256（399 张）为主 |
| 墨迹宽度占比 | 中位数 100%、均值 92% |
| 墨迹高度占比 | 中位数 100%、均值 90% |

即：**这批图标本身就画得很满，墨迹几乎撑满画布。**

所以渲染文字图标时：

- 画布用 **128×128**（与主流一致，保证缩放行为相同）。
- 字号定标必须按**字形外接盒的高度**来算（`Paint.getTextBounds().height()`），
  目标高度占画布约 **0.82**。
  - ⚠️ **不要用 `Paint.measureText()` 的返回值定标** —— 它返回的是「宽度」，
    汉字是方块字，用宽度定标会导致实际字高只有 ~40%，看起来非常小。
    这正是上一版「字太小」的根因。
- 居中用字形外接盒的 `exactCenterX / exactCenterY`，
  **不要用 `fontMetrics` 的 ascent/descent 算基线**，否则拉丁字母会偏上。
- 极端宽字形（`W`、`M`）再加一道宽度上限（约画布 0.90），防止横向出界。
- **透明底 + 不透明字形**：界面上会对图标 `setColorFilter(tint)` 染色
  （支出/收入不同颜色），带不透明底会被染成一整块色。

## 技术要求（兼容现有架构）

- 走现有的 `text://<单字>` URL 契约，在 `BundledIconLoader` 里拦截并内存渲染
  （`DataSource.LOCAL`，不落磁盘缓存 —— 名称变了 URL 就变，天然无缓存陈旧问题）。
- 兜底逻辑要放在**所有界面共用的入口**，而不是逐个界面打补丁：
  - `CategoryRepository.buildCategoryTree()` —— 覆盖分类管理、排序、内置列表；
  - `CategoryIconHelper.findCategoryIcon()` —— 覆盖账单、统计、详情等 20+ 界面。
- 保持 `BundledIconCoverageTest` 通过（它校验 assets 与源码 URL 的覆盖度）。
- 不要放开 `usesCleartextTraffic`。

## 交付标准

1. 装机后，分类管理页不再有任何「···」图标。
2. 新建分类：打字时预览实时跟随首字变化；不选图标也能保存，保存后列表显示首字图标。
3. 首字图标与相邻线性图标**视觉高度齐平**，不显得小。
4. 用户手选过图标的分类不受影响。
5. `assembleDebug` 与 `testDebugUnitTest` 通过。
